# 0.2 验收标准

## 本轮实现范围

沿用 Root / Xposed 技术验证路线；不在未验证的情况下切换为 Shizuku 全局传感器限制。
受保护对象由框架管理器中的用户作用域决定，发布说明仅推荐自建靶场。
自动关闭只支持自建靶场，未授权扩大到真实 App。保护持续到进程结束，包括后台。

1. 启用引导必须区分未安装、停用、版本不匹配和安装匹配；仅匹配的靶场可打开。按钮直接进入指定测试页，不跳转下载站、不自动获取高权限。返回首页重新检查状态；点击时重新校验版本。
2. 任何安装状态都不能被描述为 Hook 或防跳转验收成功。
3. 即使广告页面和按钮匹配，父页面未知也不得点击、返回或重试；版本/页面错误、无焦点、超时等条件保持保守决策。
4. 普通页面不自动操作。靶场 Activity 因系统重建时不得重复启动广告测试。
5. CI 自动构建并运行现有回归和新增测试，单独报告未启用 Hook 的设备基线；不得将其冒充启用 Hook 验收。
6. GitHub 仅私有存储源码、CI、来源/风险说明。不得上传凭据、keystore、工具链、个人路径日志或发布为稳定产品。

## 尚未完成的产品级比较

先固定同一设备、Android 版本、测试 App、操作轨迹、各工具的确切版本和配置，再对照 Sensor Disabler 及一个实际可用的同类方案。工具项目存在不等于在这台设备上有效。

| 目标 | 测量方法 | 发布前门槛 |
| --- | --- | --- |
| 更容易启用 | 至少 5 名未参与开发的体验者，从安装至首次通过双组检查；记录耗时、步骤、求助和失败次数 | 不把 Root 准备时间隐藏在指标外；成功率不低于对照、耗时中位数更短 |
| 更少误伤 | 正常页面、手动点击、旋转、运动功能和非运动传感器检查；逐条记录副作用 | 固定测试集误操作为 0；已知运动功能影响必须明确告知；对照结果尚待采集 |
| 更稳定 | 同一条件下至少 100 次冷/热启动、切后台、回前台和设备重启恢复；记录漏拦、崩溃及配置失效 | 固定测试集无误操作/崩溃，漏拦不劣于对照；不能据此宣称所有设备稳定 |

这些样本门槛只用于早期研发，不足以代表整个市场。现阶段全部对比指标为 **NOT MEASURED**。

## 公开发布关卡

- 完成真实 Hook 的 `baseline` / `hooked` 成对验收，记录确切镜像和框架版本。
- 补齐上表的对照记录，不发布“更好”的无证据结论。
- 由熟悉中国互联网不正当竞争的执业律师审查实际功能、授权和宣传；私有托管也不是法律免责。
- 再取得所有者明确的公开发布授权。现有私有仓库授权不包含公开。
